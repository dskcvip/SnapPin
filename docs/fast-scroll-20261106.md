# macOS 快速手动滚动采样优化（2026-11-06）

## 用户日志依据

实体 Intel Mac / macOS 13.6.6，提交 98b56f7，3344×1834 原始像素采集（逻辑区域 1672×917）。屏幕录制授权及预览排除正常。第一轮快滚无 noMatch，12 次扩展和 24 次已截区域定位，不能把现象直接归因为找不到重叠。慢滚每帧总耗时中位数约 394ms；快滚最长 1262ms，远超 80ms 定时器间隔。原链路对每帧做原生 PNG 压缩与 Dart PNG 解码。

## 本次修改

- macOS 长图首帧及后续帧使用 RGBA 传输：CoreGraphics 原区域、原 bestResolution、原预览排除规则不变；在后台原尺寸提取像素，跳过连续帧 PNG 编解码。PNG 采集接口仍保留，Windows 路径不变。
- RGBA 使用 TransferableTypedData 发送至拼接 isolate。拼接会保有输入像素，避免调用方复用缓冲破坏已截内容；去除内部重复整帧复制。
- 保留往返滚动、滚动条跳转、脱离锚点缓冲及回锚恢复规则。仅在需要缓存脱离帧时编码恢复用 PNG，正常采样不编码原图。
- 不改变原图宽度或分辨率，不改变逐行 PNG 导出及画布内存保护；预览仍独立缩小。
- 增加 transport、原生 capture/pack/total、预览缩略图生成耗时、包含预览的完整采样周期及忙时跳过的定时器次数日志。不清理用户日志。

## 验证方法与边界

新增原始像素 worker 回归覆盖快滚、反向滚动、固定导航、滚动条跳转及回锚恢复、输入缓冲复用、非法尺寸和逐像素导出一致性。macOS 原生回归使用同一 CGImage 的 PNG 与 RGBA 验证尺寸、通道、行方向，并经过实际 worker 拼接；CI 必须出现 runtime-smoke-long-raw-ready 标记才可打包。颜色比较容忍原 PNG 配置文件与 sRGB 转换的 16 级偏差，桌面 alpha 要求 255。

本地 AOT 基准 tool/benchmark_long_capture.dart 使用日志中的 3344×1834 帧尺寸和同一往返路径，PNG 解码与匹配每帧 199–231ms，RGBA 匹配每帧 10–44ms。此数字不含 CoreGraphics、平台传输或真实浏览器滚动，不代表 Mac 真机 FPS。原生 CI 负责通道方向/颜色与实际滚轮路径，不代替用户同一浏览器页面的速度验收。

采样仍有序串行，80ms 计时器忙时不并发采图，避免帧乱序与无界内存。不能保证任意速度跳过整个选区仍有重叠；无法定位时保留已截内容并提示回到已截区域，不凭空补图。
