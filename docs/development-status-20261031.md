# 开发与验收状态（2026-10-31 本轮更新）

## 本轮修改

- 长图结果页：拼接线程直接输出原分辨率首段 PNG（最多 1024 行），新窗口首先展示首段，再加载完整图片。完整长图仍以 1024 行分块显示，采用更快的无损 PNG 编码。保存、复制和编辑继续使用完整原图。
- 移除打开贴图时立即执行的马赛克预览解码；改为进入编辑时加载，避免长图显示与预览同时重复解码。
- 新增 `long-result-first-tile-ready` 和 `viewer-tiles-ready` 日志，可观察首段就绪、完整块加载的时间。尚未测得新版原生窗口实际首帧延迟，不能声称空白时间为零。
- OCR 返回文字块坐标。Windows 把放大与分段坐标换回原图像素；macOS 从 Vision 的归一化、左下角坐标换算为原图左上角坐标。
- OCR 结果默认按原图坐标展示，保留文字的行列位置和空白间距，可横向、纵向滚动；支持切换纯文本。左侧原图保留图形、颜色和背景。文字排版不代表恢复截图里的所有图形、字体和颜色。
- `复制全文` 和翻译使用按位置排序后的纯文本；未实现 HTML/RTF 等带格式复制。

## 本轮继续完成

- 贴图阴影接入 `setHasShadow`，默认原生状态与菜单状态一致；菜单与 Y 快捷键共用切换函数。L 补齐锁定快捷键。悬浮球仍不添加阴影。
- Windows OCR 移到后台工作线程，通过 Win32 消息返回主线程；禁止同时启动多个识别任务，关闭时取消未返回的回复，避免访问已释放的引擎。
- Windows 主应用开启标准库异常处理，修复默认 `_HAS_EXCEPTIONS=0` 导致解码异常穿过 future 时终止进程的问题；插件编译选项不变。
- Windows 打印修正为 `Start-Process -FilePath ... -Verb Print`；未实际向打印机发送任务。
- macOS Vision 与 Windows 返回相同的文字布局结构，并同样拒绝重叠 OCR 请求。共享 Flutter 设置、工具条、贴图、长图、识别窗口和所有本轮 UI 修改。
- 新增显式 Release 自检入口，使用生成的本地文字图片，检查真实原生阴影、OCR 布局、识别时的窗口响应、重复请求、错误恢复和识别中关闭。测试不注册热键，不读取屏幕或用户配置；Windows 使用独立测试互斥锁及 APPDATA。
- macOS CI 在全量测试、通用架构编译后，运行原生 OCR 自检、托盘菜单和退出检查；通过后才生成并挂载验证 DMG。实际运行结果由 CI 日志和下载包旁的验证报告记录。
