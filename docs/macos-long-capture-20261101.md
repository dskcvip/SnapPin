# macOS 手动长截图采集修复

## 用户日志确认的现象

`snappin-2026-11-01(2).log` 中，13:57:03 屏幕录制 preflight 已为 true，普通截图正常。13:57:59 开始手动长截图，选区为 1672×917 点，Retina 原始图像为 3344×1834 像素。后续 16 次采样没有追加内容，第一次 noMatch，之后保持 still，最终由用户停止。没有崩溃记录，也没有证据证明辅助功能未授权是本次手动滚动失败的原因。

## 代码发现与处理

- 原 `WindowCaptureExclusion` 只支持 Windows。macOS 的预览窗每帧都会 hide/show，而 window_manager 的 macOS show 调用 `makeKeyAndOrderFront` 和 `NSApp.activate`，持续把焦点拉回 SnapPin。
- macOS 的截图边框没有排除出采集，只调用了忽略鼠标事件。这不能阻止窗口图像进入采集。
- macOS 子窗口通过原生通道注册采集排除；采集使用 CoreGraphics 显式窗口 ID 列表，在合成时排除预览窗。使用 bestResolution 保留 Retina 原始像素。
- 核对 Tauri `commands.rs` 2681 行附近的真机问题说明后，对齐其处理规则：长截图期间全程隐藏全屏选区层，不在帧间重新显示，避免全屏输入表面拦截滚轮；结束后沿用现有关闭和结果显示流程。
- 窗口 ID 数组按 CoreGraphics 的原始指针大小 ID 格式创建，使用 nil callbacks，不把 ID 包装成 CFNumber。
- 长图预览首次显示、复用显示和隐藏回退后的恢复均使用 `orderFrontRegardless`，不调用激活应用或切换 key window。
- 启动长截图时按选区中心查找其他应用的底层窗口，恢复其前台状态，等待活动窗口装饰稳定后采集首帧；这不调用辅助功能授权接口，也不代替用户滚动。
- 原生日志记录排除窗口 ID、目标应用 PID、当前前台 PID和采集序号；前 20 个采样记录 still 的差异值、耗时和是否隐藏预览。此后继续定期记录，便于判断画面未动还是匹配失败。

## 验证

macOS Release 自检增加原生 `longCaptureSmoke`，仅在显式 normal 自检模式下启用。它创建带确定性内容的测试窗口和覆盖其上的洋红预览窗：

1. 对照采集必须能看到洋红预览，防止空白采集被误当作排除成功。
2. 排除后采集必须看到底层内容，预览显示后原窗口仍为 key window。
3. 发送系统滚轮事件，确认事件穿过忽略鼠标的预览，送达内容窗口。
4. 对 0→40→80→40→0→120 点的滚动路径采集真实图像，由实际 Dart 拼接器检查向下扩展与回滚，最终高度必须保持原始倍率且没有重复追加。

CI 仍运行全量 Flutter 回归、原生 OCR、托盘和退出、双架构与 DMG 挂载检查。任何自检失败都阻止打包。测试窗口在完成或失败时关闭，不修改真实用户的浏览器页面、配置或授权。

CI 中的受控窗口回归不能代替用户 Intel macOS 13.6.6 上的真实浏览器、触控板、多屏 DPI 验收。具体通过结果以该提交的 CI 和下载包旁验证记录为准。
