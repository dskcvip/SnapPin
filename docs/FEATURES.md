## 一、概览

SnapPin 是一个截图 + 标注 + 贴图工具，五个窗口共用一个 React 前端包：

| 窗口 | label | 作用 | 形态 |
|---|---|---|---|
| 悬浮球 | `ball` | 常驻小圆球，单击截图、拖动移动 | 无边框透明、置顶、可拖动 |
| 截图浮层 | `overlay-m{n}` | 每台显示器一个，承载冻结图 + 选区 + 标注 | 透明、全屏尺寸、无边框 |
| 贴图窗 | `pin-{uuid}` | 把图片钉在屏幕上，可缩放/透明/锁定 | 无边框、可置顶、可穿透 |
| 菜单窗 | `ball-menu` | 自绘浅色菜单，托盘 / 悬浮球 / 贴图右键共用 | 透明、无边框、复用同一窗口 |
| 主窗 | `main` | 设置与快捷键说明（**界面已写，入口未接**，见 10.3） | 普通窗口（当前运行时不会创建） |

技术栈：Tauri v2 + React 19 + TypeScript + Vite，采集用 xcap，剪贴板 arboard，OCR 用 rten（纯 Rust ONNX 运行时），二维码用 rxing。

三个入口都能开始截图：**全局热键 `Ctrl+1`** / **单击悬浮球** / **托盘图标单击或右键 → 截图**。

## 二、截图采集 ✅

### 2.1 采集与浮层

- **多显示器全量采集**：一次性用 xcap 抓取所有显示器整屏，各自存成临时 PNG（`%TEMP%/snappin/snap-{uuid}.png`）。
- **冻结画面**：浮层显示的是采集瞬间的静态图，不是实时屏幕——弹菜单、悬停高亮都不会污染截图内容。
- **一屏一窗**：每台显示器一个透明全尺寸浮层，各自独立选区，互不干扰。
- **采集是异步的**：浮层可能先出现、图后到；前端轮询 `overlay_context().ready`，`ready` 由 `true` 变 `false` 说明会话已结束，窗口自关兜底。
- **采集期间隐藏悬浮球**，避免球被拍进截图。

### 2.2 选区

| 操作 | 行为 |
|---|---|
| 拖拽 | 拉出选区，四角显示角标，选区上方实时显示 `宽 × 高`（物理像素） |
| 重新拖拽 | 在任意位置按下即**清空当前选区并重新框选**（选区一次性确定，不支持拖角改尺寸） |
| 单击（不拖） | 小于 3px 的拖动不成立，选区保持为空 |
| 右键 | 已有选区 → 清空选区；没有选区 → 退出截图 |
| 悬停 | **未出选区时**显示放大镜与颜色读数；此时按 `C` 复制 HEX |
| `Esc` | 退出截图（长截图进行中时改为"停止滚动并出图"） |
| `Enter` | 完成并复制到剪贴板 |

**坐标系约定（贯穿全链路）**：前端一律用**逻辑像素**，Rust 在裁剪/光栅化时统一乘 `scaleFactor` 转物理像素。这条约定是清晰的根因防线——高 DPI 屏上混用两种单位会出现"选区对但图偏移"。

与之配套的一条硬约束：**逻辑坐标必须允许小数**。逻辑坐标 = 物理像素 / scaleFactor，2x 屏下一个物理像素就是 0.5 逻辑像素，所以 `rect` 在 Rust 侧是 `f64`（`RectPayload`）。曾经写成 `i32/u32`，serde 在反序列化阶段就拒收浮点：

```
复制失败: invalid args `rect` for command `confirm_selection`:
invalid type: floating point `484.71484375`, expected u32
```

该错误**只在非 100% 缩放的机器上复现**（macOS Retina、Windows 125%/150%），100% 缩放的机器上坐标恰好是整数、完全看不出来。现已改为浮点并补了反序列化回归测试（`rect_payload_accepts_fractional_coords`）。

> 四角小方块（`.handle`）目前是**视觉角标**，没有绑定拖拽改尺寸的事件。要调整选区范围需重新框选。

### 2.3 选区阶段的放大镜与取色 ✅

不额外走一步截图，**拖选/悬停时就能取色**：

- **放大镜气泡**：边长 156px，**4 倍平滑放大**，取样区域 = 156/4 = **39 逻辑像素**（约 2.5–3 个字宽，能完整看清单个字）。
  - 中心十字准星标出"当前取的是哪一个像素"；
  - 边缘自动翻转，贴近屏幕边界时气泡跑到另一侧；
  - 底部显示色块 + **HEX 读数**。
- **取色**：移动即实时刷新读数；按 `C` 复制 HEX，气泡提示"已复制 #RRGGBB"（1.2 秒后消失）。**取色只在"还没框出选区"的阶段可用**——出了选区之后浮层进入标注模式，`C` 不再响应（原工具条上的拾色器按钮已按用户要求撤下，`pick` 工具的手势代码保留但无 UI 入口）。
- **像素来源**：不用 `<img>` 直接 `getImageData`（asset 协议下 canvas 会被判跨域污染，读取抛 SecurityError），改由 Rust 的 `read_image_bytes` 直接下发 PNG 字节 → `Blob` → `createImageBitmap`，读取永远合法。

> 历史：早期版本是 140px / 8 倍最近邻，取样区只有 17.5 逻辑像素，一个字都装不下，且抗锯齿笔画被放大成方块。现已改为 4 倍平滑，取舍见 `.workbuddy/memory/2026-10-21.md`。

### 2.4 工具条自适应

- 工具条跟随选区定位，选区靠近屏幕底部时**自动翻到选区上方**。
- 浮层窗口较窄时，工具条 `max-width: calc(100% - 12px)` + `flex-wrap: wrap`，不会超出窗口被裁掉。
- 窗口宽度 < 440px（容器查询）时隐藏透明度滑条等次要控件，优先保证主按钮可用。

### 3.1 通用行为

- **`Ctrl+Z` 撤销**：逐条弹出最近的标注（暂不支持重做）。
- **属性面板**：颜色、线宽、字号/暗度等滑条，右侧常显实时数值（等宽数字 + 固定最小宽度，拖动时面板不跳宽）。
- **文字输入法友好**：输入框是 textarea，中文输入法原生可用；输入期间 `Enter`/`Esc`/`Ctrl+Z` 归输入框，不会误触发"完成/取消截图"。
- **二次编辑**：标注数据是可序列化结构，重绘走同一份数据；Canvas 预览与 Rust 光栅化共用一个模型。
- **文字类标注走位图通道**：文字/序号/水印在 UI 层用 Canvas `fillText` 光栅化成 base64 PNG，核心层只做 alpha 合成，不引入字体库（保住 core-algo 零依赖 + 安装包不背中文字体）。

### 3.2 智能擦除的实现与边界 ⚠️

零依赖**同步波前扩散**：把区域像素清空后，从区域外沿向内逐像素填充，取值 = 已填充四邻像素均值。同轮内后写入的像素看不到本轮新值（状态在轮末统一翻正），因此渐变背景上不会出现菱形阶梯。

- 平坦背景（纯色、线性渐变）：效果接近 OpenCV inpaint；
- **强纹理/文字背景：只能"抹平"，无法重建纹理**——这是零依赖实现的固有上限，接 OpenCV inpaint 才能进一步改善。

## 五、长截图（滚动拼接）✅

工具条「长截图」按钮：框选一个区域 → 自动滚动页面 → 实时拼接成一张长图。

### 5.1 流程

1. 校验选区（**至少 80px 高**）与会话代号，防重入；
2. 浮层改为**光标穿透**，滚轮事件落到下层真实页面；
3. Windows 给浮层设置 WDA 采集排除（失败则退化为"采集前后隐藏浮层"）；
4. 注册长截图专用全局 `Esc`；
5. 采首帧建会话 → 驱动循环滚轮滚动、每步匹配重叠、累积拼接。

### 5.2 算法与参数

| 项 | 值 |
|---|---|
| 每步滚动 | 3 行（一格滚轮 ≈ 3 行） |
| 匹配 | 行哈希 + 模板匹配求垂直偏移，输出置信度 |
| 无匹配重试 | 连续 2 次无匹配 → 改为轻滚 1 行重建重叠 |
| 放弃阈值 | 连续 4 次无匹配 → 认为页面不再滚动/内容整体替换，收尾出图 |
| 步数上限 | 600 步（≈1800 行，对应 32000px 算法高度上限） |
| 停到底判定 | 帧相似度达到"静止"阈值即认为已到底 |

### 5.3 交互

- **状态条**：滚动中常驻，实时显示缩略图（逐步长高）+ 当前高度 / 步数 + Esc 提示。
- **`Esc` 语义**：拼接中按 Esc = **停止滚动并出图**，不是丢弃（半途按 Esc 的预期是"就到这里"）。
- **结果面板**：复制 / 贴图 / 保存三选一。贴图时长图逻辑尺寸封顶为主屏幅面的 **70%**，避免一张图糊满屏幕。

### 5.4 限制 ⚠️

- 依赖页面响应滚轮事件；内部用 JS 虚拟滚动且不回滚的页面可能拼不全；
- 页面有吸附/懒加载动画时，重试机制会多花几步；
- 只在 Windows 实测，macOS 未验证。

## 六、OCR 文字识别 ✅

工具条「识别文字」按钮：框选区域 → 点按钮 → 结果面板。

- **模型**：PaddleOCR **PP-OCRv4 mobile**（det 4.7 MB + rec 10.4 MB + 6623 字字典），经 **rten**（纯 Rust ONNX 运行时）本地推理，**完全离线**。
- **流程**：DBNet 检测文本行 → 按阅读顺序排序 → CRNN + CTC 解码 → 每行输出 `{ text, score, box }`。
- **坐标系**：返回的框是"**相对选区左上角的逻辑像素**"，前端可直接画高亮框，无需换算。
- **结果面板**：每行显示置信度百分比 + 文本 + 单行「复制」；顶部「复制全部」按阅读顺序拼成多行文本；行多时面板内滚动。
- **性能**：det 推理全高清区域约 0.8s、4K 约 3s，全程在 `spawn_blocking` 里跑，不冻界面；模型首次加载后缓存常驻。
- **模型缺失的处理**：工具按钮上显示一个小圆点（`ocr_models_status` 预检）；点下去若模型缺失，返回**带目录路径和下载说明的错误**，面板原样展示，不会崩溃。

### 6.1 模型目录优先级

1. 环境变量 `SNAPPIN_MODELS_DIR`（测试/特殊部署）；
2. debug 构建：仓库根 `models/ocr`（开发期免配置）；
3. release：`{app_data_dir}/models/ocr`
   - Windows `%APPDATA%\com.snappin.dev\models\ocr`
   - macOS `~/Library/Application Support/com.snappin.dev/models/ocr`

模型**不进安装包**，按需下载到固定目录；仓库 `models/` 是权威副本（含 SHA256 与直链），`scripts/fetch_models.py` 负责取回。

## 七、二维码 / 条码识别 ✅

工具条 `▤` 按钮：在选区内**拖出子区域** → 识别该区域（不是整个选区，避免圈一小块却扫到圈外的码）。

- **格式**：QR Code、EAN-13、Data Matrix 等 rxing 支持的全部码制。
- **一图多码**：返回数组，每个码带 `format` / `text` / 定位点 `points`（4 点，相对选区左上角的逻辑像素）。
- **结果面板**：逐条显示格式标签 + 内容 + 「复制」；内容匹配 `^https?://` 时额外出现「打开」按钮。
- **链接安全**：`open_url` 只放行 http/https，其它协议一律拒绝——二维码内容不可信，不给 `file:` / 自定义协议开口子。
- **空结果是正常返回**（空数组 + "未识别到二维码/条码"提示），不是错误。
- 多码识别最坏情况要做象限递归，4K 全屏达百毫秒~秒级，因此走 `spawn_blocking`。

## 八、贴图窗口 ✅

把截图（或剪贴板图片）钉在屏幕上，当参照物、做对照、临时便签。

### 8.1 基本交互

| 操作 | 行为 |
|---|---|
| 拖动 | 按住图片拖动（锁定时禁用） |
| `Ctrl+滚轮` | 缩放 0.1x ~ 8x |
| `Alt+滚轮` | 窗口透明度 0.15 ~ 1（步进 0.05） |
| 右键 | 打开自绘菜单（见 8.3） |
| `Esc` | 关闭贴图 |

> ⚠️ 缩放是 **CSS `transform: scale()`**，窗口尺寸不变、`overflow: hidden`：放大到 >1 会被窗口边界裁掉，缩小到 <1 会在窗口内留一圈透明边距。当前没有"缩放时同步改窗口尺寸"的逻辑，所以缩放更适合小幅微调，不适合把贴图当放大镜用。

### 8.2 悬停工具条（可关闭）

鼠标进入显示一排按钮：复制 / 保存 / 透明度滑条 / 置顶 / 穿透 / 锁定 / 关闭。

- **「穿透」是临时的**：开启后窗口对鼠标透明，**5 秒自动恢复**——否则点了穿透就再也点不回来。
- **工具条可整体关掉**（右键菜单「✓ 工具栏」/ `H` 键），关掉后贴图只剩图片；拖动与右键菜单仍可用，保证能再开回来。
- 工具条在窄贴图上会换行，超窄时隐藏透明度滑条。

### 8.3 右键菜单（完整结构）

```
不透明度  ─────●────────────  100%      ← 第一项，滑块（15%~100%）
──────────────────────────────────────
图像处理                              ▸
复制图像
保存图像
──────────────────────────────────────
鼠标穿透
──────────────────────────────────────
✓ 边框阴影                          Y
✓ 窗口置顶                          T
  锁定                              L
✓ 工具栏                            H
──────────────────────────────────────
关闭                              Esc
```

- **一级菜单宽 200px**，二级菜单 `max-content`（最小 152px），**一二级之间 1px 缝**（按面板内边距换算，不是视觉贴边）。
- **滑块为什么放第一项**：贴图最常调的就是透明度。且它不走 `menu_action`（那条路第一步是关菜单），而是每个拖动值调 `pin_set_opacity` → Rust 转 `pin-set-opacity` 事件给贴图窗，**菜单不关、拖动即所见**。
- **勾选态**由贴图窗上报快照（`pin_publish_flags`），菜单打开时 `pin_flags` 读回——关掉再开，勾选和滑块位置都不会失真。

### 8.4 图像处理（`图像处理 ▸`）

| 项 | 键 | 说明 |
|---|---|---|
| 向右旋转 / 向左旋转 | `1` / `2` | 顺时针 / 逆时针 90°，窗口跟着换宽高、**中心不动** |
| 水平翻转 / 垂直翻转 | `3` / `4` | 勾选表示当前已翻转 |
| 灰度化 / 反色 | `5` / `6` | 勾选表示当前已应用 |
| 图像不透明度 ▸ | — | 25 / 50 / 75 / 100%，**把 alpha 烤进像素** |
| 调整亮度 ▸ | — | 变亮 / 变暗 / 重置，底部显示当前倍率 |
| 重置所有处理 | `0` | 回到原图 |

实现要点：

- **非破坏性、不累积**：永远是「原图 + 参数」重算，连续调亮度不会越调越糊（避免反复重采样）。
- **复制的就是所见**：处理结果会落盘成贴图的新源图，`复制图像` / `保存图像` 读的正是它；旧产物在换图/关窗时删除，临时目录不会膨胀。
- **前端光栅化**：canvas `filter` + 中心变换出 PNG dataURL，经 `pin_apply_edit` 上传，Rust 校验 PNG 头 → 写临时文件 → 换源图 → 按新尺寸（中心不动）调窗口。

### 8.5 两个"不透明度"的区别（容易误解，特意分开命名）

| | 位置 | 作用 | 导出的图 |
|---|---|---|---|
| **不透明度**（滑块） | 菜单第一项 / 工具条滑条 / `Alt+滚轮` | 只改窗口整体显示（CSS opacity） | 仍是原样不透明 |
| **图像不透明度** | 图像处理子菜单 | 把 alpha 写进像素 | 半透明 |

### 8.6 开关项

- **边框阴影**：勾选时内边框 + 外发光，取消后贴图变成纯图片（无描边、无投影）。锁定/穿透的状态环保留——那是状态提示，不是装饰。
- **窗口置顶**：置顶时压在其他窗口之上。
- **锁定**：禁止拖动，边框加虚线/状态环提示。
- **工具栏**：悬停是否显示工具条。

> 这四个开关是**每个贴图独立**的，不是全局偏好；新贴图默认全开。

## 九、菜单体系 ✅

托盘、悬浮球、贴图右键共用**同一个自绘菜单窗**（浅色圆角面板 + 勾选列 + 右对齐快捷键 + 分组分隔线）。不用系统原生菜单的原因：原生菜单样式不可控、右侧放不了快捷键提示、无法做勾选与子菜单层级。

### 9.1 三阶段定位协议

```
Rust 记录锚点 + 把菜单窗停到屏外 (-32000,-32000)
  → emit menu-open
前端量 offsetWidth/offsetHeight
  → menu_fit(w, h)
Rust 按锚点定位（贴边自动翻转）、resize、focus
```

- **窗口始终 `visible`**：WebView2 对隐藏窗口节流 `requestAnimationFrame`，隐藏就量不出尺寸。所以"是否打开"用**有没有锚点**判断，不用 `is_visible()`。
- **子菜单尺寸一次预留**：所有隐藏子菜单也参与测量，`menu-fit` 一次性给足外扩范围，展开时不再 resize——否则窗口会在指针下方跳动，hover 被打断。
  - 代价：菜单贴着屏幕右边缘时会整体翻到光标左侧，右侧留一条给子菜单的空白。
- **首次打开丢事件**：菜单窗第一次创建时 `menu-open` 监听还没挂上，所以 `menu_state` 会返回 `kind` / `pinLabel`，前端挂载时补一次。

### 9.2 应用菜单（托盘 / 悬浮球）

```
截图                      Ctrl+1
剪贴板贴图                Ctrl+2
显示 / 隐藏悬浮球
──────────────────────────
关于 SnapPin
打开运行日志
──────────────────────────
退出
```

快捷键注册失败时，菜单顶部插一条橙色告警行（如「Ctrl+1 已被其他程序占用」）——**不让失败静默**。

## 十、悬浮球 / 托盘 / 设置窗

### 10.1 悬浮球

- **单击截图**，**按住拖动**移动（左键）。
- **右键打开菜单**。
- **位置持久化**：拖动后写盘，且保存的是**球心**（窗口留白随阴影变化时，存左上角会让球在屏幕上平移）。节流：位移超过 1px 才写。
- 尺寸默认 56px（40~80 可配）；颜色与尺寸都来自 `config.json` 的 `themeColor` / `ballSize`，启动时读取。

### 10.2 托盘

- **左键单击 = 右键单击 = 打开同一份自绘菜单**（Windows 上已屏蔽系统默认弹出）。
- **macOS 例外**：左键弹自绘菜单，**右键弹系统原生 NSMenu**（截图 / 贴图 / 悬浮球 / 屏幕录制权限 / 日志 / 关于 / 退出）。这条原生菜单是**保命兜底**——本应用没有 Dock 图标也没有 ⌘Q，自绘菜单一旦建不出来（WKWebView 建窗失败、主线程投递超时），用户就没有任何退出入口，只能命令行 kill。原生菜单由系统绘制，不经过 webview / 前端，永远点得动。
- tooltip 会带上快捷键注册失败信息。
- 双保险：即使热键被占用，托盘和悬浮球仍能截图。
- 「关于 SnapPin」用系统默认浏览器打开项目主页（`gitee.com/dskcvip/snappin`）；「打开运行日志」直接打开落盘日志文件。
- macOS「屏幕录制权限…」直达 `系统设置 → 隐私与安全性 → 屏幕录制`，换包后授权失效时用它自助恢复。

### 10.3 设置窗 ⏳（组件就绪，入口未接）

`main.html` + `src/windows/MainWindow.tsx` 已实现设置界面：快捷键说明、主题色取色器、悬浮球尺寸滑条（40~80）、「保存设置」按钮。**但目前没有任何代码创建 `main` 窗口**，也没有菜单项指向它，所以在运行时看不到这个界面。

配置层面是通的：`get_config` / `update_config` 可读写 `config.json`，改完重启生效。要开放界面只差两件事——加一个建窗函数、在菜单里加一项。主题色与球尺寸当前只能手工改 `config.json`。

## 十一、配置 / 日志 / 临时文件 ✅

| 类型 | 位置 |
|---|---|
| 配置文件 | `{app_config_dir}/config.json`（Windows `%APPDATA%\com.snappin.dev\config.json`） |
| 运行日志 | Windows `%APPDATA%\com.snappin.dev\snappin.log`；macOS `~/Library/Application Support/com.snappin.dev/snappin.log` |
| 截图/贴图临时 PNG | `%TEMP%/snappin/snap-{uuid}.png` |
| OCR 模型 | `{app_data_dir}/models/ocr`（release）/ 仓库 `models/ocr`（debug） |

**配置字段**：`themeColor`、`ballSize`、`ballPosition`（x/y，球心）、`shortcutCapture`、`shortcutPinClipboard`、`saveDir`。

### 日志为什么要落盘

release 构建是 `windows_subsystem = "windows"`，进程没有控制台，所有 `eprintln!` 直接进无效句柄——**静默丢弃**。于是用户报"按 Ctrl+1 没反应"时无法区分：热键没注册上 / 注册了但回调没触发 / 回调触发但采集中途失败。

现在在启动最早期把 **stderr 整个重定向**到日志文件（`SetStdHandle` + 文件句柄 `Box::leak` 成活到进程结束），既有的、遍布 `commands.rs` 的 `eprintln!` 一行不改就全部落盘；另有 `logln!` 给热键回调、托盘点击这类"没有 eprintln 但必须留痕"的地方埋点。单文件超 2 MB 截断重开（目的是排障，只看最近一次）。

托盘菜单「打开运行日志」可直接打开该文件。

### 单实例

重复启动会把已运行的窗口拉到前台，不产生第二个进程（避免两份热键注册互相抢占）。

### 已知限制

- **混合 DPI 多显示器**：浮层位置按 `物理像素 / scaleFactor` 换算，不同缩放因子的副屏可能有偏差。
- **Linux Wayland**：xcap 走 X11 路径，纯 Wayland 需 XWayland。
- **macOS**：屏幕录制/辅助功能授权流程依赖 xcap，**尚未在真机验证**；dmg 为 ad-hoc 签名，首次打开会被 Gatekeeper 拦（右键→打开，或 `xattr -dr com.apple.quarantine`）。
- **保存对话框**：阻塞式原生对话框，仅 PNG/JPEG，未做 E2E 验证。
- **智能擦除**：强纹理背景只能抹平，无法重建纹理。
- **长截图**：依赖页面响应滚轮；JS 虚拟滚动页面可能拼不全。
- **贴图数量**：无上限保护。

## 十五、构建与发布 ✅

### Windows

```bash
cd E:\PixPin
npm run typecheck
npx tauri build --bundles nsis
```

产物：`target/release/SnapPin.exe`（≈17 MB）、`target/release/bundle/nsis/SnapPin_0.1.2_x64-setup.exe`（≈4.8 MiB）。
只出可执行文件、不出安装包：`npx tauri build --no-bundle`。

> **⚠️ 不要把 `target/debug/SnapPin.exe` 当交付物直接运行**：
> debug 构建下 Tauri 会把 `WebviewUrl::App("xxx.html")` 解析到 `devUrl`
> （`http://localhost:5173`，见 tauri `manager::get_app_url` 的 `#[cfg(dev)]`
> 分支）。没开 vite dev server 时**所有 webview 都是死的**——悬浮球不渲染、
> 菜单窗不应答（日志里只有 `menu open requested`、永远没有 `menu shown`）、
> OCR/翻译/设置全打不开；同时 Tauri 还会自动建一个加载 `index.html` 失败的
> 默认窗口，显示成**黑框 +「无法访问此页面」**。自测/分发一律用 release。
> 排查：release 启动后日志应出现 `[ui:ball] ball mounted`，没有这行即 webview 没加载。

> 本机沙箱注意：`npx tauri build` 前需把真实 toolchain 的 bin 提到 PATH 最前（rustup 代理 `rustc.exe` 在沙箱里被拦，会让 tauri-cli 解析 `rustc -vV` 失败并 panic）：
> `export PATH="/c/Users/dskc/.rustup/toolchains/stable-x86_64-pc-windows-msvc/bin:$PATH"`

### macOS

Windows 上**无法**产出 dmg（缺 `xcrun` / `hdiutil` / `codesign` / `lipo` 与 Apple SDK）。走 GitHub Actions：

- 流水线 `.github/workflows/build-macos-dmg.yml`（`runs-on: macos-latest`），命令为 `npx tauri build --target universal-apple-darwin --features custom-protocol`；
- 触发方式：推 `v*` tag，或 Actions 页面 Run workflow（可选单架构更快更小）；
- 产物 `SnapPin_0.1.0_universal.dmg`，**arm64 + x86_64 合并的 fat binary**，M 系与 Intel 通用；
- `minimumSystemVersion: 11.0`（Big Sur）；
- `signingIdentity: "-"`（ad-hoc）：Apple Silicon 必需的最低门槛，但无开发者证书、未公证。

细节见 [BUILD-macos.md](BUILD-macos.md)。
