## 23:00 OCR 卡死真因+端到端验证（提交 0a33c49）
**真因**：`ocr_show` 是同步命令 → Tauri 把它跑在**主线程的 webview IPC 回调里** →
在那个上下文建 WebView2 窗口死锁。设置窗没事是因为它从托盘事件进来，不在 IPC
回调里（同代码不同上下文，所以前两轮修锁/修线程都没修对）。

**定位方法（可复用）**：加 `SNAPPIN_TEST_DOC_WINDOW=ocr|settings` 调试钩子，
借 single_instance 回调（主线程）直接调真实命令函数，逐步排除：
主线程直调 ocr_show → 正常 714ms；block_on 堵主线程 → 建窗死锁 15s；
spawn（=真实 IPC 线程模型）→ 正常 324ms + ocr mounted。

**修复**：ocr_show/trans_start/open_settings_window 改 async + 窗口操作
run_on_main_thread 投递主线程 + 通道等结果；ocr_show 先关浮层再开结果窗；
cancel_capture 改回同步（误改 async 会让关窗跑非主线程，更糟）。
**端到端实测成功**：合成鼠标点球→拖选区→点识别 → 1 秒识别 10 行 → 浮层关闭 →
OCR 窗 mounted，全程无卡死。

**Windows 建窗铁律（本项目）**：
1. 同步命令别建窗（会在 IPC 回调里死锁）→ 用 async 命令
2. 窗口操作（建/关/显/隐）必须回主线程（run_on_main_thread + 通道等结果）
3. 别"起工作线程建窗 + 主线程通道等待"（建窗要枚举显示器走事件循环线程，会互等）
4. 合成输入时通时断（桌面隔离），成功时能走完整用户流程——多试
