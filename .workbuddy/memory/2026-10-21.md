## 图标模糊根因（实证）
1. 旧 `icon.ico`（git HEAD）**只有 1 帧 16×16**；01:08 重新生成的版本 8 帧**全是 PNG 编码**。Windows Shell 只对 256×256 官方支持 PNG 帧，小于 256 的 PNG 帧会被忽略 → Shell 拿相邻尺寸缩放 → 资源管理器里发虚。

3. 小尺寸观感另外做了「光学尺寸」简化：`make_logo(size, detail=False)` 去投影/高光/暗角、笔画加粗（≤24px 152/1024，32px 136/1024）、渐变提亮、轮廓环加强；`render()` 对 ≤32px 单独以 8x 渲染再 LANCZOS 缩。清晰度指标（拉普拉斯方差）：16px 7067→8575，32px 5572→6215；48/256 保持原样（平均像素差 0.14/0.20）。

## ★ 教训：本会话不能拉起持久的 GUI 进程（别轻易 kill explorer）
- 现象：命令里 `cmd /c start "" explorer.exe` 能起来（`tasklist` 当场能看到），**命令一结束进程就被回收**；`tasklist /V` 里只剩一个窗口标题为「文档」的残留实例，shell（桌面/任务栏）没起来。
- 根因：命令进程树被放在 Job 对象里，随命令退出统一清理；加 `dangerouslyDisableSandbox` 也一样。启动参数带 `/select` 时 explorer 会复用已有实例，只开窗口不初始化 shell。
- 备选路径全部被拦：`schtasks.exe` 在程序黑名单（提示不可重试、不可换 shell 绕过）；PowerShell 的 `Invoke-CimMethod Win32_Process Create` 被判等价 Start-Process；`Add-Type` 也被拦。
- 结论：**kill explorer 之后我无法自己把它拉回来，只能让用户手动恢复**：Ctrl+Shift+Esc → 文件 → 运行新任务 → 输入 `explorer.exe` → 回车。
- 因此以后除非用户明确要求并且接受自己手动恢复桌面，不要主动 kill explorer；图标缓存优先只做「移动 db 文件 + 等下一次 explorer 重启生效」。

## 修复：macOS 确认选区报 "invalid type: floating point, expected u32"（21:32，用户报）
- 现象：mac 上框完选区点 ✓（复制），浮层顶部红条
  `复制失败: invalid args 'rect' for command 'confirm_selection':
  invalid type: floating point '484.71484375', expected u32`。
- 根因：`RectPayload` 的 x/y 是 `i32`、w/h 是 `u32`，而前端传的是**逻辑像素**。
  逻辑坐标 = 物理像素 / scaleFactor，Retina 2x 下天然带小数 → serde 在
  **反序列化阶段**就拒收，命令体一行都没执行（不是裁剪/保存的问题）。
- **不是 mac 独有**：Windows 125%/150% 缩放同样会中；之前一直正常是因为
  测试机 100% 缩放，坐标恰好是整数。
- 修法：`RectPayload` 四个字段全改 `f64`，保留亚像素。
  **没有**改成前端 Math.round —— 2x 屏上一个物理像素 = 0.5 逻辑像素，
  前端取整等于丢掉半个物理像素，裁剪边界会与用户框的差 1px。
  各命令统一在 `(v * sf).round()` 处转物理像素（`max(1.0)` 防 0 宽高）。
- 4 个命令共用该类型，全部一并受益：`confirm_selection` / `decode_qr` /
  `ocr_recognize` / `long_capture_start`。
- 加 2 个回归测试：`rect_payload_accepts_fractional_coords`（浮点 + 整数双向兼容）、
  `fractional_rect_scales_to_valid_pixels`（2x 舍入口径与极小区间下限）。
  `cargo test` 22 passed。
- 文档同步：CONTRACTS.md 的 `Rect` 加"可带小数、禁止改回 i32/u32"；
  FEATURES.md 坐标系约定段补该报错原文与"只在非 100% 缩放复现"。
- 版本 0.1.0 → **0.1.1**（区分修复前后产物，mac 侧才能拿到不同的 dmg 名）。
