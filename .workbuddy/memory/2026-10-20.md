## r10-r15 轮次：「截图采集超时」根因 + 悬浮球品牌化（2026-10-20 20:05）

### 超时根因（重要，非采集性能问题）
用户按 Esc 会调 `cancel_capture`，它无条件 `close_overlays + monitors.clear()`。
若取消后**立刻**再点悬浮球截图，这条迟到的 cancel IPC 会在新会话已 show 浮层之后执行：
关掉**新浮层**、清空**新会话数据** → 新浮层永远 `ready=false` → 15s 后报「截图采集超时」。

**修复三层**：
1. **会话代号隔离**：`AppState.session: AtomicU64`，`do_capture` 开头 `fetch_add(1)`；
   `overlay_context` 返回 `sessionId`，前端取消/确认回传；`cancel_capture`/`confirm_selection`
   校验 `id != current → 忽略`（日志 `cancel ignored: stale session`）。
   采集期（前端还没 sessionId）收到取消 → 记 `cancel_pending`，由 `do_capture` 在 show 前消费。
2. **采集互斥**：`AppState.capturing: AtomicBool` + `CaptureGuard`（Drop 释放）。
   原防重入靠"浮层窗口是否存在"，但预创建有上百 ms 空窗，重复触发会启动第二遍采集，
   复用第一遍浮层（页面不重载→状态陈旧）并把浮层自身截进冻结图。
3. **前端按"新一轮会话"重置**：`startedRef` 在 `overlay-ready` 事件与 visibilitychange 时重置
   （页面复用不重载，用挂载时刻做基准会立刻判超时）；事件里清 rect/draft/shapes/error；
   `ready→false` 自关改为**连续 15 次**确认（防陈旧 readyRef 误自关）。

### 悬浮球品牌化
应用/托盘图标已换 "深墨蓝圆底 + 橙 S"，但**悬浮球是前端 CSS 画的**，不会跟着变。
`BallWindow.tsx` 的 `PinGlyph` → `SGlyph`（SVG，与 make_icons.py 同一套贝塞尔：
`M700 300 C560 210 420 215 375 330 C340 430 480 470 600 500 C680 520 690 590 648 655 C600 730 470 745 360 700`，
stroke-width 104，投影+暗边+高光做体积感）；`ball.css` 改深墨蓝三段渐变 + 内阴影 + 橙色 hover 光环。

## 21:00 修复「截图采集失败/超时」与「复制后 Ctrl+V 贴图无反应」

### 根因 1（用户报的"采集失败"）：浮层拿到数据后，兜底轮询把已就绪页面覆盖成错误页
`OverlayWindow.tsx` 的 `poll()` 把超时判定放在最前面且**不区分是否已就绪**，
而 `setInterval(kick, 400)` 兜底轮询永不停止 → 会话就绪 15 秒后，每次轮询都走到
`if (Date.now() - startedRef > 15000) setError('截图采集超时，请重试')`，
把已经正常显示的冻结图/工具条整个替换成错误页。用户点球后若超过 15 秒才拖选区，
就看到"截图采集失败"。**与采集本身无关**，日志里 `captured 2 monitor(s)` 一切正常。
修复：超时分支加 `!readyRef.current` 门控；`ready→false`（会话结束）分支补
`setTimeout(poll, 300)` 继续低频探测，保住"双屏漏关自关"的三级保障。

### 根因 2：Ctrl+V 武装热键注册在工作线程 → 注册成功但永远收不到按键
`arm_paste()` 由 `confirm_selection`（async 工作线程）调用，`RegisterHotKey` 把
`WM_HOTKEY` 投递到**注册它的那个线程**的消息队列，工作线程没有消息循环 → 静默失效
（无任何错误日志）。Ctrl+1/Ctrl+2 在 setup 主线程注册所以正常。
修复：新增 `windows::post_to_main`（`run_on_main_thread` **不等待**，可在主线程本身调用
而不会自等待死锁），`arm_paste`/`disarm_paste` 的 register/unregister 都改为投递主线程。
日志加 `Ctrl+V armed (gen N)` / `Ctrl+V disarmed` 便于确认。

### 顺手加的诊断与 UX
- 新增命令 `ui_log`：前端日志汇到 Rust stderr，前缀 `[ui:<窗口label>]`（release 没 DevTools）。
- `do_capture(app, state, src)`：src = ball / cmd / hotkey / menu，一眼看出谁触发的。
- `end_capture_session(app, state, why)`：why = confirm-ok / cancel-capture / xcap-error /
  cancel-pending / save-before-dialog；同时打印 monitors/overlays 剩余数。
- `show_overlays` 逐窗打印 set_size/set_position/show/focus 的 Err 与 is_visible，
  以及 `captured N monitor(s) in Xms` / `session N ready, Xms total`。
- `ball_command("capture")` 遇到 "already in progress" 视为成功（不再把重复触发当错误）。
- **进入截图态但未选区时整屏压暗 20%**（`.overlay-dim`）：冻结图与桌面像素一致，
  没有这层压暗用户以为"点了球没反应"，会去补按 Ctrl+1 → 重复采集 + 报错。

### 自测套路（本次全部实测通过）

### 为 macOS 改的代码（都是 cfg 门控，Windows 行为不变，已回归验证）
1. **透明窗口**：tauri.conf.json 加 `app.macOSPrivateApi: true`，
   同时 Cargo 的 tauri 依赖必须加 `macos-private-api` feature——
   否则 `tauri-build` 直接报 "dependency features does not match the allowlist" 构建失败（已踩）。
2. **不占 Dock**：setup 里 `app.set_activation_policy(tauri::ActivationPolicy::Accessory)`。
   ⚠️ 必须放在 `let handle = app.handle();` **之前**：`App::handle()` 是不可变借用，
   之后再调需要 `&mut self` 的 `set_activation_policy` 会 E0502。
3. **屏幕录制权限**：core-platform 新增 `ensure_screen_capture_permission()`，
   macOS 走 `#[link(name="CoreGraphics", kind="framework")]` 的
   `CGPreflightScreenCaptureAccess` / `CGRequestScreenCaptureAccess`；未授权时截图全黑。
4. **建窗线程**：macOS 的 NSWindow 只能主线程建，改了两处——
   - `precreate_overlays_hidden`：macOS 版改成 `run_on_main(build_overlays_hidden)`
     （**同步等建完**，因为 show_overlays 不会兜底建窗，异步会导致浮层不显示）；
     Windows 版保持在工作线程直接建（主线程会死锁）。
   - `create_pin_window`：拆成两个 `#[cfg]` 同名定义（别用 `if cfg`+`return`，
     函数尾部没有表达式会 E0308）；macOS 版 `run_on_main_thread` + mpsc 等结果。
     签名从 `tauri::Result<()>` 改为 `Result<(),String>`，调用点改成 `??` / `?`。
5. **坐标单位**：xcap 0.9.8 源码确认——Windows 的 `x()/y()` 是物理像素，
   macOS 的来自 `CGDisplayBounds` 是**点**（逻辑）。新增 `MonitorShot::logical_origin()`，
   `show_overlays` 与贴图定位都改用它，避免 Retina 副屏位置被除两次变成 1/2。

## 23:20 悬浮球外阴影被裁成"切面"（用户报）→ 已修

### 根因（实证）

**注意：不是"阴影不正圆"，是窗口太小把阴影切了。**

### 改动
1. `BALL_MARGIN` 10 → 24（球心到边 52 ≥ 静止 50 / hover 50.3），hover 阴影同步收敛：
   `0 5px 12px` + `0 0 0 2px` 环（原来是 `0 8px 20px` + `0 0 0 3px`，缩放后需要 63px，必裁）。
2. 位置语义从"窗口左上角"改为**球心**（config 新增 `ballPosCenter`，旧值按旧留白 10 换算一次），
   否则留白从 10 改到 24 会让球在屏幕上平移 14px。
3. Windows 会把小于 **SM_CXMINTRACK（实测 136px）** 的窗口强行加宽：104x104 → 136x104。
   `.min_inner_size(1.0,1.0)` **无效**（限制来自系统不是 winit）。所以：
   - 位置必须按**实际** inner_size 分别取半宽/半高（否则球心横偏 16px）；
   - 球窗口现在是 136x104 的非正方形。
4. **`set_position` 时序坑（重要）**：`build()` 返回后系统还会做"最小尺寸修正 + 重新放置"，
   此刻 set_position 会被覆盖（现象：球固定跳到主屏中部某处，且每次位置不同，
   `want=(832,348) got=(1569,708)`）。破法：immediate 设一次 + `t+250ms` / `t+900ms`
   各补一次（`place_ball_center` 会读回 outer_position 打日志核对）。
   实测三次都 `want==got`，180ms 那一版不够（必须 ≥250ms）。
