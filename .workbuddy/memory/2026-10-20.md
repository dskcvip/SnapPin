- 项目定名 SnapPin（开发过程禁现 pixpin 字样），git 初始化并完成首次提交（main 分支，62 文件）。
- E2E 最小闭环全部验证通过：悬浮球渲染/拖动/位置持久化 → 单击截图（双显示器 xcap 采集）→ 全屏浮层冻结图 → 拖拽选区（十字准线/尺寸标签/八向手柄）→ 复制（剪贴板 350×220 图片 ✓）/贴图（置顶贴图窗 ✓）/Esc 取消 → 工具栏跟随选区+底边翻转。
- **根因修复 1（白屏）**：裸 cargo run 时 tauri 的 dev cfg 为 true（custom-protocol 特性未启用），WebviewUrl::App 解析到 devUrl(http://localhost:5173) 连接被拒 → 白屏。修复：src-tauri/Cargo.toml 增加 custom-protocol = ["tauri/custom-protocol"] 特性透传，构建/运行均带 --features custom-protocol。
- **根因修复 2（浮层空白+无事件+探针线程静默）**：Tauri 文档 Known issues——Windows 上在**同步命令/事件处理器**内创建 webview 会死锁/空白。修复：所有建窗流程（start_capture/ball_command/pin_from_clipboard/confirm_selection 的建窗/handle_capture/handle_pin_clipboard）改 async 命令 + tauri::async_runtime::spawn_blocking。
- 其他修复：工具栏原是 .sel 兄弟节点导致渲染在屏幕底部中央且 pointer-events:none 不可点 → 移入 .sel 内部 + pointer-events:auto + below/above 翻转类；截图期间自动隐藏悬浮球（BALL_HIDDEN_BY_CAPTURE AtomicBool），close_overlays 时恢复。
- 构建命令备忘：`export PATH="/c/Users/dskc/.rustup/toolchains/stable-x86_64-pc-windows-msvc/bin:$PATH" && cargo build -p snappin --features custom-protocol`；前端 npm run build 后必须重新 cargo build（generate_context! 宏在编译期读 dist）。
